# 思畅 AI：朗读接管与音频保存

## 行为

- 页面：`https://sichang.xyz/*` 聊天页。
- 两个发起入口，走同一条合成/播放/落盘流程：
  - 点击消息下方的「朗读」：脚本截下官方请求，**官方播放器不会出声**，改由脚本分段请求、边下边播。音色同样取面板里选定的那个，忽略官方请求自带的 `voice`。
  - 面板底部手动输入：文本 + 音色 + 语速，点「合成」或 `Ctrl/Cmd+Enter`。音色与语速会记住（`localStorage`）。输入区随内容自动增高（上限 132px 后内部滚动，滚动条隐藏），草稿也会记住。输入框为空时（首次打开、清空后失焦）自动预填一句短试听文本并以灰暗样式显示，聚焦进入编辑即自动清空；预填文本不算草稿，不会写入 `localStorage`。空文本时「合成」禁用；有内容时输入框右上角出现「×」，只清输入并保持焦点，空框或预填试听文本时隐藏。合成开始后按钮变「暂停」，再点变「继续」：暂停会同时停住流式消费和当前播放，已完成的段仍可单独播放，继续后从原位置接着合成；`Ctrl/Cmd+Enter` 仍是直接发起新的合成。
- 记录操作：记录头一行显示折叠箭头、时间、总时长/合成进度 `n/m`、单行摘要、段数、整条播放/暂停按钮、整条重生成按钮和「⋯」菜单；音色与语速、复制原文、下载整条 WAV、删除都在菜单里。点摘要只选中整条；点记录头其余区域选中整条并收起/展开该条下方的分段列表（箭头随状态旋转，折叠后仍保留这一行）。输入框填入完整全文；摘要单行截断，不再展开全文。菜单挂在 Shadow DOM 根节点上，不会被面板滚动区裁掉，贴底时自动向上翻。
- 播放跟随输入框：顺序播放推进到新的一段、或实时时间线播到下一段时，输入框自动填入该段文本并同步选中状态；输入框正在被编辑或存有尚未提交的手动改动时不覆盖，避免冲掉草稿。
- 选中与编辑：点分段行（不是按钮）选中该段，输入框显示该段文本；编辑后点该段 ▶ 旁的 ↻ 图标，请求按输入框里的文本发出，成功后写回该段文本、整条摘要和可下载 WAV，并直接播放新音频。图标只作用于自己所在的那一段。点记录头或摘要选中整条，输入框显示完整全文，此时记录头的整条重生成会按输入框里编辑后的全文逐段原地重合成（分段数需与记录一致，否则沿用各段原文）。再次点同一条不会覆盖输入框里尚未提交的编辑；开始新合成或点输入框右上角的「×」会取消选中。
- 面板折叠与拖动：单击标题栏收起/展开（标题栏内的按钮除外），折叠状态会记住；拖标题栏移动，位置会记住；双击标题栏复位成自动贴底（避开页面底部输入框）。标题栏已压缩，清空全部记录（标题栏「清空」）改为二次点击确认：第一次按钮变「确认清空」，3 秒内再点一次才删除，点别处或超时自动取消。
- 右下角「语音捕获」面板同步记录一次合成：开始时就按计划分段建好子条目，逐段显示 `待合成 → 合成中（时长随数据增长）→ 完成/失败`，记录头同时显示总进度 `n/m`；**每段一完成就能单独播放，不必等整条合成结束**；全部结束后把各段拼成一条 WAV，只用于整条下载。播放统一走分段顺序播放，记录头提供整条播放/暂停按钮。
- 实时播放控制挂在当前播放分段展开的面板上：合成下载完时整条可能还在时间线上播，面板里是暂停和停止图标。暂停只停声音并保留进度，再点变「继续」并从中断处重排；进度条按这一段已经播到的位置点击跳转，再换算成整条时间线上的位置。收起面板后点回这一段，仍能继续。
- 记录头的整条播放/暂停按钮：没有播放队列时从第一段开始顺序播放；正在顺序播放时显示暂停，再点继续；实时时间线正在播或暂停时也复用这个按钮。暂停期间主按钮与当前分段面板状态一致。
- 分段子条目（核心 UI）：每条记录下按计划段建好列表，逐段显示文本、状态和时长。点分段行选中该段并把文本填进输入框，播放推进时输入框也会跟着当前段走；点某段的 ▶ 就从该段开始**顺序播放**，播完自动接下一段。合成还没完成时，如果下一段还没好，面板显示「等待下一段」，该段一完成自动接上。**播到谁，谁就展开自己的控制面板**，同一时间只展开一个。面板里时间、可点击跳转的进度条和播放/暂停、停止、重播、下载等图标按钮同排显示；暂停后「继续」和「停止」入口都保留。单段「重生成」不放在展开面板里，而是每个分段行 ▶ 旁的 ↻ 图标按钮（不占文字宽度，说明写在 title/aria 里）：播放/暂停时点击会先停掉时间线或目标段再替换；合成进行中也能重生成**已经完成**的段，只替换该段并按长度差重排实时时间线；成功后自动播放新音频。合成期间当前面板还会保留一个黄色的「停止合成」，切到分段顺序播放后也能停掉整个合成。
- 合成被「停止」或中途失败时，还没轮到的段标成「未合成」，已经收到部分数据的段保留为完成状态、仍可播放；整条 WAV 只拼接实际收到的段。
- 进度条：记录头用 `n/m` 表示合成阶段按已完成段数推进；各分段行以自己的状态和时长表示单段进度；展开面板里是该段真实的播放进度，点击可跳转。实时时间线与分段顺序播放共用当前段的这一条进度。
- 合成比实时快，长文本下载完时整条可能还在时间线上播：这段时间当前段面板里是暂停和停止图标，记录头按钮同步显示暂停；播完面板收起、所有段恢复为可单独播放。暂停/继续只影响声音，不会重新请求；点「停止」立即静音并复位。开始分段顺序播放前会先停掉实时时间线，避免叠音。
- 一次新的合成/朗读会停掉上一段朗读和面板里正在播放的音频，不会两路声音叠在一起。
- 面板会自动抬到底部输入框上方，避免挡住「发送」；标题右侧可收起成小条，状态会记住。
- 最多保留最近 20 条，删掉或挤掉的记录会释放 blob URL。

## 分段规则

- 先按句末标点（`。！？!?；;…`）和换行切句，再把短句攒到 **160 字**上限；超长句硬切。
- 首段先攒够 **0.5 秒**音频再起播：开头几个网络块常比实时慢，直接播会在第一句里留出 30–220ms 的补白。
- 单段失败重试 2 次；仍失败且一个字节都没收到时，把这段对半再拆（短于 40 字则放弃该段）。
- 播放当前段时预取下一段，缩短段间停顿。
- 长文本分段主要是为了稳定性：整段合成失败就全没了，分段后失败只影响一句。

## 接口契约

| 项 | 值 |
| --- | --- |
| 请求 | `POST /api/tts`，JSON `{text, voice, rate, format}`，`format` 当前为 `"pcm16"` |
| 响应 | `content-type: audio/pcm`，**流式**裸 PCM16，单声道 |
| 采样率 | 响应头 `X-Sample-Rate`（实测 `24000`），缺失时按 24000 处理 |

接管依赖两个约定：

- 官方请求由脚本用一帧静音响应顶替，否则官方播放器会弹「语音合成失败」。
- 脚本自己发的分段请求带 `X-Sichang-Segment: 1` 头，据此跳过接管，避免递归。

站点里 `/api/tts` 只有一个调用点：消息组件的 `useTts` hook（固定 `format: "pcm16"`）。「音频创作」页走的是 `/api/audio/jobs` 任务接口，不在接管范围；面板的手动入口直接用同一契约发请求，不模拟点击。

站点改版时先看 Network 里的 `/api/tts`：路径、请求体字段、采样率头或音频格式任一变化，都会表现为面板「失败」或没有声音。

## 分段与重生成

- 每段的 PCM 单独保存，WAV 按段顺序拼接；子条目顺序就是播放顺序和最终音频顺序。
- 点某段从该段开始**顺序播放**：首次播放时才按需生成该段的 WAV blob；播完自动接下一段，播到谁谁展开自己的面板。暂停/继续、拖动进度只影响当前段；同一时间只放一条音频，开始新的会先停掉上一条。
- 合成中切到分段顺序播放时，实时时间线只停住声音、不中止合成，之后也不会自动切回时间线；等新段合成好由顺序播放接着播。
- 合成中顺序播放到尚未完成的段时，当前面板显示「等待下一段」；该段完成后自动接着播，失败或未合成则跳过。
- 重生成只替换目标段，不动其他段；**音色取面板当前选中的音色**，语速与格式沿用这条记录的设置；成功后重拼 WAV、刷新总时长，并清掉该段旧的 blob URL 和播放状态，然后自动从该段开始顺序播放。顺序播放正播到或正等待这一段时，先停下这个队列。入口是该段 ▶ 旁的 ↻ 图标按钮。
- 合成进行中也可以重生成已经完成的段：更新总字节数和实时时间线进度，目标段在当前位置之前时平移后续偏移，正播到目标段内则从该段开头重排；未完成的段和正在重生成的那一段仍不可点。
- 选中某段时，重生成请求使用输入框里的文本；成功后把新文本写回该段和整条记录，摘要、复制原文和后续整条重合成都会跟随。未选中该段时仍使用它保存的文本；请求失败时保留旧文本，避免文字与音频对不上。音色始终使用面板当前选择，换音色后直接点 ↻ 就会用新音色重做这一段。
- 重生成失败、返回空数据或采样率与整条不一致时，保留原段不变，该段图标短暂变红显示 `!`。
- 同一时间只允许一个段在重生成：目标段图标旋转并禁用，其他段的 ↻ 暂时禁用，但其他已完成段仍可播放；重生成只停目标段相关的播放，不打断其他段。
- 记录头的 ↻ 是整条重生成：按分段顺序复用逐段重生成，**原地替换所有分段，不新建记录**；结束后重拼一次 WAV，并从第一段开始自动播放。整条被选中且输入框全文的分段数与记录一致时，用输入框文本覆盖各段；否则沿用各段原文。合成进行中不可整条重生成，避免和正在写入的段抢数据。
- 「⋯」菜单里不再提供「重新合成」；要新建一条记录，直接用面板底部输入框点「合成」。
- 合成中途断流时，已经收到的部分仍标记为可播放，和整条 WAV 里的内容一致。

## 边界

- 点「停止」或开始下一次朗读时，已收到的部分照常保存成一条较短的记录。
- 单条上限 64 MB（约 22 分钟），超出后继续消费流但不再保存。
- 只在 `@grant none` 直接注入页面世界时可用，否则碰不到页面的 `fetch` 与 AudioContext。
