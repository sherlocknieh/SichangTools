# 朗读接管与流式 PCM 播放（思畅）

## 为什么抓不到官方音频

思畅的「朗读」不走 `<audio src=...>`：它 `fetch('/api/tts')` 拿一条 PCM16 流，用 `ReadableStream` 边读边转 `AudioBuffer` 交给 Web Audio。页面上没有可下载的媒体 URL，也没有 `speechSynthesis` 记录。

所以捕获点只能放在**网络层**：包装 `window.fetch`，把官方请求改成脚本自己的分段请求。

## 接管流程

1. 包装 `window.fetch`，命中 `/api/tts` 且不是脚本自己发的分段请求（没有 `X-Sichang-Segment` 头）时接管。
2. 从请求体取 `{text, voice, rate, format}`，按句子切段。
3. **立即给官方返回一个只有一帧静音的响应**：官方播放器的状态机能正常走完，不会弹错误提示，也不会发出整段声音。
4. 脚本用同一接口逐段取音频，每收到一块 PCM 就转成 `AudioBuffer` 排进 `AudioContext` 时间线（`playhead` 递增），实现边下边播。
5. 同时把各段 PCM 累积到一个面板记录里，全部结束后封装成 WAV（44 字节头、单声道、16 bit、采样率取 `X-Sample-Rate`）。

## 关键约束

- **必须给官方一个正常结束的响应**：返回空 body 会走官方的失败分支（`return !1`），用户会看到「语音合成失败」。
- **自己的请求必须打标记**：否则第二次请求又被接管，无限递归。
- **克隆/累积要控制上限**：单条超过 64 MB 后继续把流消费完（避免背压），但不再保存。
- **流可能被中断**：点停止或切换朗读会 abort，已收到的部分照常落盘，不算异常。
- **音频上下文在点击的同一个任务里创建/恢复**：`ensureAudioContext()` 放在接管处理里，借用用户手势解除自动播放限制。
- **分段失败要能降级**：重试 2 次仍失败且没有数据时对半拆，避免一句话拖垮整段朗读。
- **不要用轮询或 DOM 监听**：按钮图标与 React 状态会变，接口才是稳定契约。
- **下载完成 ≠ 播放结束**：合成速度远快于实时，整条会一次性排进时间线；UI 必须在当前播放分段的展开面板里保留「暂停」和「停止」两个入口，否则长文本会有数分钟停不下来，点播放还会叠音。
- **首段要预缓冲**：先攒 0.5 秒再起播，否则开头几个网络块到达间隔会在第一句里留下可听的补白。
- **暂停/跳转按 PCM 重排**：不保留每个块的 AudioBuffer（长文本会攒出上百兆 Float32），而是停掉已排的 source，按当前播放位置从各段 PCM 重新建一条 buffer 起播；新到的块再按 `playhead` 接在后面。
- **进度锚点要重设**：当前时间线位置是 `startOffset + (currentTime - timelineStart)`；数据来晚、暂停继续或跳转时都要重设锚点，否则进度条会跑到声音前面或回跳。
- **暂停不终止合成**：暂停只停声音、保留进度；继续时从暂停点重排。结束定时器按剩余音频重算，暂停、跳转后都要重新计时。
- **合成暂停要停住消费**：面板「暂停」把 `synthesisPaused` 置位，`consume` 在读流前和拿到块后都等闸门，`speak` 与任务循环也等同一道闸门；同时暂停当前播放（时间线或分段队列），继续时只恢复原本正在播的那一路，再从同一条流接着读。停止或中止会话时必须释放闸门，否则异步循环会一直挂着。
- **分段完成即可播**：合成开始时按计划段预建子条目，某段响应读完就把它标成完成并启用播放，不必等整条；状态用 `待合成/合成中/完成/失败/未合成`，边收边显示该段已拿到的时长。
- **合成中切到分段播放不能叠音**：点已完成的分段时，实时时间线只停在当前位置（停已排 source，不 abort 合成、不改捕获状态），之后由分段顺序播放接管，不再自动回到时间线；期间到达的数据照常累积，最终 WAV 仍然完整。
- **分段要单独存**：每段的 PCM 与文本一起保存，WAV 按段拼接；否则无法只重生成一段。
- **分段 WAV 按需生成**：点击某段播放时才把它拷成 WAV blob 并缓存，避免每条记录的所有段都提前占一份内存；重生成后要 revoke 该段旧 URL。
- **同一时间只放一条音频**：分段顺序播放、实时时间线、跨记录的试听共用一个主动播放概念，开始新的之前先停掉其他的，避免叠音。
- **重生成要守住整条契约**：替换段后必须重建 WAV 和 blob URL，并停掉正在播放的顺序播放队列；采样率与整条不一致时拒绝替换，避免拼出非法 WAV。
- **重生成只锁目标段**：其他段的 PCM 与 blob URL 独立，不需要跟着停或禁用；只把目标段标 `busy`，其余段照常试听。

## 分段顺序播放（面板核心）

- 面板以分段为播放单位：点任意已完成段的 ▶，就从该段开始按列表顺序播放，`ended` 后自动接下一段；播到谁，谁的分段面板展开，上一个面板收起。
- 同一时间只展开一个面板。实时时间线用 250ms ticker 把 `livePosition` 按累计字节约成秒数映射到分段，播放位置换段时自动切换面板；用户手动点开别的段时不被抢回，直到播放真正进入下一段。
- 合成中顺序播放到尚未完成的段时，记为 `waitingFor`，面板显示「等待下一段」；该段 `done` 后自动接上，`failed/skipped` 则跳过。
- 暂停只暂停当前段音频，保留队列和位置；继续从原位置播。停止会清空队列、把当前段归零并收起面板。
- 记录头的整条播放/暂停按钮复用同一套队列：无队列时从第一段开始，有队列时暂停/继续；实时时间线播放/暂停也由它控制。等待下一段时按钮显示播放图标并禁用，下一段开始后恢复暂停图标。合成中暂停实时播放后再点播放会从暂停点继续；若此时合成结束，会话丢弃，记录转为可从第一段顺序播放。
- 合成中切到分段顺序播放后，实时面板会收起；当前分段面板保留黄色的「停止合成」，避免整个合成失去停止入口。
- 实时时间线暂停后，点回那一行仍按时间线模式打开面板（「继续」/「停止」），不会误切成分段队列；点其他分段才切换到顺序播放。
- 整条 WAV 只作为下载产物保留，不再创建整条 `<audio>` 播放器；跨记录、跨模式仍只允许一路声音。

## 选中文本与重生成

- 选中状态是 `{ record, segment }`：点分段行选中该段，点记录头/摘要选中整条；官方输入框分别填入该段文本或完整全文。
- 重生成只在 `selection` 指向该段时读取官方输入框文本，否则用 `segment.text`；请求成功后才写回 `segment.text` 并把 `record.text` 重算成各段文本拼接。失败保留旧文本，避免标签与音频不一致。
- 单段「重生成」是每个分段行 ▶ 旁的图标按钮，目标固定为该行分段；`ready/playing/paused/capturing` 都可用（该段必须已完成），播放/暂停时先停掉时间线或该段再替换。按钮不依赖选中；选中该段并编辑官方输入框时，请求才使用输入框文本。成功后自动从该段开始顺序播放，合成中会先暂停实时时间线。
- 捕获中替换段会改变整条 PCM 长度：必须同步 `record.bytes` 与 `session.receivedSeconds`，并按长度差平移时间线偏移；目标段正被实时播放时从该段开头重排，时间线处于暂停（顺序播放）时只更新 `pausedOffset`、不启动声音。
- 记录头的整条重生成复用 `regenerateSegment`：外层持有 `record.regenerating`（`keepLock`），按段顺序原地替换，非合成状态把 WAV 重建推迟到全部结束后做一次，再从第一段自动播放；不新建记录，合成进行中禁用。
- 选中整条时，若官方输入框全文的分段数与记录一致，就把文本按段覆盖后用于整条重生成；否则使用各段 `segment.text`。
- 开始新的合成或删除选中记录时清掉选中状态，避免输入框和下一次重生成的目标错位。

## 段间衔接

每段数据到达就立即调度，`startAt = max(playhead, currentTime + 0.06)`，所以段与段之间只留极短的空隙。预取下一段（当前段响应头一到就发下一段请求）用来抵消合成延迟，比逐段串行快。
