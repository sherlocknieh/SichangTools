# 朗读接管与流式 PCM 播放（思畅）

## 为什么抓不到官方音频

思畅的「朗读」不走 `<audio src=...>`：它 `fetch('/api/tts')` 拿一条 PCM16 流，用 `ReadableStream` 边读边转 `AudioBuffer` 交给 Web Audio。页面上没有可下载的媒体 URL，也没有 `speechSynthesis` 记录。

所以捕获点只能放在**网络层**：包装 `window.fetch`，把官方请求改成脚本自己的分段请求。

## 接管流程

1. 包装 `window.fetch`，命中 `/api/tts` 且不是脚本自己发的分段请求（没有 `X-Sichang-Segment` 头）时接管。
2. 从请求体取 `{text, voice, rate, format}`，按句子切段。
3. **立即给官方返回一个只有一帧静音的响应**：官方播放器的状态机能正常走完，不会弹错误提示，也不会发出整段声音。
4. 脚本用同一接口逐段取音频，每收到一块 PCM 就转成 `AudioBuffer` 排进 `AudioContext` 时间线（`playhead` 递增），实现边下边播。
5. 同时把各段 PCM 累积到一个面板记录里，全部结束后封装成 WAV（44 字节头、单声道、16 bit、采样率取 `X-Sample-Rate`）。

## 关键约束

- **必须给官方一个正常结束的响应**：返回空 body 会走官方的失败分支（`return !1`），用户会看到「语音合成失败」。
- **自己的请求必须打标记**：否则第二次请求又被接管，无限递归。
- **克隆/累积要控制上限**：单条超过 64 MB 后继续把流消费完（避免背压），但不再保存。
- **流可能被中断**：点停止或切换朗读会 abort，已收到的部分照常落盘，不算异常。
- **音频上下文在点击的同一个任务里创建/恢复**：`ensureAudioContext()` 放在接管处理里，借用用户手势解除自动播放限制。
- **分段失败要能降级**：重试 2 次仍失败且没有数据时对半拆，避免一句话拖垮整段朗读。
- **不要用轮询或 DOM 监听**：按钮图标与 React 状态会变，接口才是稳定契约。
- **下载完成 ≠ 播放结束**：合成速度远快于实时，整条会一次性排进时间线；UI 必须比较 `playhead` 与 `currentTime`，在播期间保留「暂停」和「停止」两个入口，否则长文本会有数分钟停不下来，点「播放」还会叠音。
- **首段要预缓冲**：先攒 0.5 秒再起播，否则开头几个网络块到达间隔会在第一句里留下可听的补白。
- **实时播放的变速只能用 Web Audio**：`AudioBufferSourceNode.playbackRate` 会连音高一起变，没有 `preservesPitch`；而 `<audio>` 播不了还在到达的流。所以面板整条 WAV 与分段试听保音高，实时时间线换速会变调。
- **暂停/跳转/换速按 PCM 重排**：不保留每个块的 AudioBuffer（长文本会攒出上百兆 Float32），而是停掉已排的 source，按当前播放位置从各段 PCM 重新建一条 buffer 起播；新到的块再按 `playhead` 接在后面。
- **进度锚点要重设**：当前时间线位置是 `startOffset + (currentTime - timelineStart) × rate`；数据来晚、暂停继续、跳转或换速时都要重设锚点，否则进度条会跑到声音前面或回跳。
- **暂停不终止合成**：暂停只停声音、保留进度；继续时从暂停点重排。结束定时器按 `剩余音频 / 倍速` 重算，暂停、跳转、换速后都要重新计时。
- **分段完成即可播**：合成开始时按计划段预建子条目，某段响应读完就把它标成完成并启用播放，不必等整条；状态用 `待合成/合成中/完成/失败/未合成`，边收边显示该段已拿到的时长。
- **合成中试听不能叠音**：试听已完成的段时，实时时间线只停在当前位置（停已排 source，不 abort 合成、不改捕获状态）；这段播完或暂停后按 `pausedOffset` 从各段 PCM 重排继续，期间到达的数据照常累积。
- **分段要单独存**：每段的 PCM 与文本一起保存，WAV 按段拼接；否则无法只重生成一段。
- **分段 WAV 按需生成**：点击某段播放时才把它拷成 WAV blob 并缓存，避免每条记录的所有段都提前占一份内存；重生成后要 revoke 该段旧 URL。
- **同一时间只放一条音频**：整条试听、分段试听、实时时间线共用一个主动播放概念，开始新的之前先停掉其他的，避免叠音。
- **重生成要守住整条契约**：替换段后必须重建 WAV 和 blob URL，并停掉正在播放的整条 WAV；采样率与整条不一致时拒绝替换，避免拼出非法 WAV。
- **重生成只锁目标段**：其他段的 PCM 与 blob URL 独立，不需要跟着停或禁用；只把目标段标 `busy`，其余段照常试听。

## 段间衔接

每段数据到达就立即调度，`startAt = max(playhead, currentTime + 0.06)`，所以段与段之间只留极短的空隙。预取下一段（当前段响应头一到就发下一段请求）用来抵消合成延迟，比逐段串行快。
